# A System That Notices

**Detecting silent distribution shift in deployed machine-learning models**

DS635 - Machine Learning System Engineering - term project

---

## 1. Summary

A deployed model does not announce when the world it was trained on has changed. It keeps returning well-formed
predictions while quietly getting worse. This project builds a small monitoring system that watches a stream of
data batches and raises an alert when something has shifted.

We build five detectors and one standard statistical baseline, **inject known shifts** into three real datasets
(so the right answer is known), and measure for every detector:

- how often it catches each kind of shift (sensitivity, with confidence intervals),
- how quickly it catches it (detection lag),
- how often it raises a false alarm,
- the full sensitivity versus false-alarm trade-off curve.

Everything is regenerated by one command, and every number in the documentation is produced directly from the
result files, so the text cannot disagree with the data.

## 3. The problem, in plain language

Imagine a model that predicts whether a borrower will default on a loan. It was trained on last year's borrowers.
After deployment it answers every request without errors, so ordinary uptime monitoring sees nothing wrong. But if
the kind of applicant changes, or the default rate rises, or the link between a borrower's profile and default
changes, the model becomes confidently wrong. This is called **distribution shift** (or model drift).

We write X for the inputs (borrower features) and Y for the outcome (default or not). Three different things can
change, and each needs a different detector:

| Kind of shift | What changes | What stays the same | Example |
|---|---|---|---|
| **Covariate shift** | the inputs, P(X) | the rule linking inputs to outcome, P(Y given X) | applicants become younger |
| **Label shift** | the outcome rate, P(Y) | how inputs look within each outcome, P(X given Y) | default rate rises from 7% to 15% in a recession |
| **Concept drift** | the rule linking inputs to outcome, P(Y given X) | nothing is guaranteed | the same debt ratio now means something different |

The central difficulty: **a detector that only looks at inputs cannot see concept drift**, because in concept drift
the inputs do not move. Detecting it requires labels, which in real life arrive late and are scarce.

## 4. How the system works

1. **Split.** For each run, the data is shuffled and cut into a *reference window* (the "normal" data, 10
   batch-sizes of rows) and a *stream* of 30 batches. The two share no rows. Batch size is the number of rows
   divided by 40.
2. **Inject a shift.** Starting at stream batch 10, one of three shifts is applied, either abruptly or ramped in
   over 6 batches, at one of three strengths (mild, moderate, severe).
3. **Fit.** All detectors, and a small reference model (logistic regression), are fitted on the reference window only.
4. **Score.** Every batch of the stream gets a score from every detector.
5. **Alert rule.** An alert fires only when a score stays above its threshold for **2 consecutive batches**.
   This suppresses one-batch noise at the cost of about one batch of delay.
6. **Repeat.** Every scenario is run 20 times, each with a new seed, new split, new reference and freshly fitted detectors.
7. **Diagnose.** `diagnosis.py` combines the alerts into one verdict: covariate, label, concept-or-mild-label,
   label-or-subtle-covariate, or none.

Scale: 3 shift types x 3 severities x 2 onset speeds x 20 repetitions = **360 runs per dataset, 1,080 in total**.

### Thresholds are calibrated per dataset

A score's natural noise level depends on the batch size, so one fixed threshold cannot suit every dataset. For each
dataset we first run 40 *clean* streams (no shift, seeds never used in evaluation) and measure each detector's noise.
The alert threshold is then `max(default floor, 1.25 x 99th percentile of the clean scores)`. The default floors are
the conventional values (for example 0.10 for PSI), so calibration can only make a detector less trigger-happy, never more.
The baseline is deliberately not tuned.

### The three shift injectors

- **Covariate:** shift the target feature by `severity x IQR / 1.349` (a robust estimate of one standard deviation).
- **Label:** resample post-onset batches so the positive rate rises by 5, 10 or 20 percentage points.
  Pre-onset batches are never touched.
- **Concept (pure):** in the region where the target feature is at or above its median, relabel some positives as 0;
  in the region below the median, relabel exactly as many negatives as 1. Every input column and the number of positives
  per batch stay exactly the same (this is tested), so only the input-to-outcome relationship moves. Severity is the
  fraction of positives swapped (0.25, 0.5 or 1.0).

## 5. The detectors and the baseline

| Detector | How it works | Expected to catch | Expected to miss |
|---|---|---|---|
| `psi_agg` | Population Stability Index of each feature against the reference; the maximum is taken | covariate | label, concept |
| `kl_agg` | KL divergence of each feature (current versus reference); the maximum is taken | covariate | label, concept |
| `centroid_dist` | distance between batch and reference centroids in a PCA embedding | covariate | label, concept |
| `pred_prop_psi` | PSI of a fixed model's predicted probabilities | label (and some covariate) | concept |
| `concept_signal` | how much the model's Brier score degrades on a 20% labelled sample of the batch | concept (also reacts to label shift) | - |
| `ks_baseline` | **named baseline:** per-feature two-sample Kolmogorov-Smirnov test, Bonferroni-corrected, alpha 0.01, untuned | covariate | label, concept |

**PSI versus KL.** With identical bins, PSI equals KL(current, reference) plus KL(reference, current), the symmetrised
KL divergence. Both use a log-ratio. Our `kl_agg` is only the forward term, so it is never larger than PSI on the same
data, and with the same threshold it cannot fire when PSI does not.

**Why a baseline?** It answers the question "does this system beat a simple, standard, tuning-free test?"

## 7. Experimental design

| | |
|---|---|
| **Baseline** | per-feature KS test with Bonferroni correction (alpha 0.01), untuned, same alert rule, same runs |
| **Varied** | shift type, severity, onset speed, detector, dataset; the alert threshold is also swept to draw the trade-off curves |
| **Held fixed** | the 2-batch alert rule, 30 stream batches, onset at batch 10, reference window size, batch size, reference model, 20% label sample, seed scheme, pinned library versions |
| **Measured** | sensitivity with 95% Wilson confidence interval computed from pooled counts (20 repetitions per cell), detection lag, false-alarm rate, score AUC, sensitivity at fixed false-alarm budgets, per-batch cost |
| **Checked against hand labels** | `validation/hand_labelled_check.py` (section 9) |

### Where the system breaks, and why

1. **Pure concept drift when positives are rare.** The label-based signal is a Brier score on a small labelled sample; with few positives, swapping labels barely moves it, so sensitivity is low.
2. **Small batches.** Scores get noisier as batches shrink, so thresholds must rise and sensitivity falls.
3. **Fixed PSI/KL thresholds and small shifts.** A conventional 0.10 threshold misses small absolute covariate shifts that a significance test (the KS baseline) catches.
4. **Mild label shift versus concept drift.** Both degrade the Brier score; no detector here separates them.
5. **Conservative operating points.** Thresholds above the clean 99th percentile plus a 2-consecutive-batch rule are stacked. The confirmation-rule tables (`REPORT.md`, per dataset) show that one consecutive batch (k = 1) recovers a large part of the lost sensitivity at a false-alarm rate still well under 1%, and the trade-off curves show some detectors could do better at low false-alarm rates than their reported operating points.

### Recommendations

1. Calibrate thresholds per deployment from clean data at the real batch size; do not reuse thresholds across datasets. Then choose the confirmation length k from the confirmation-rule table; with calibrated thresholds k = 2 was over-cautious here.
2. Keep a KS test with Bonferroni correction running as a cheap, tuning-free first line for input drift; use PSI/KL only with a threshold read from a trade-off curve.
3. For label shift, use `pred_prop_psi` together with `concept_signal`.
4. For concept drift you need labels: budget a labelled sample, monitor a proper score such as Brier, and expect weak sensitivity when positives are rare.
5. Never read `concept_signal` alone; use `diagnosis.py`, and treat its ambiguous verdicts as "investigate".
6. `centroid_dist` was never the best detector for any shift on any dataset and can be dropped.

## 11. Design decisions and pitfalls

- **Robust scaling.** Shift size uses `IQR / 1.349`, not the standard deviation, because outliers in `DebtRatio` inflate the standard deviation by orders of magnitude.
- **Winsorising.** Inputs are clipped to the reference window's 1st and 99th percentile before scaling, both for the reference model (extreme values make logistic regression numerically fragile and machine-dependent) and for the PCA embedding. Winsorising the PCA did not rescue `centroid_dist` on Give Me Some Credit, so its weakness there is not only an outlier effect.
- **Check the IQR of any new target feature.** An IQR of exactly 0 (Adult's `capital-gain`) means a shift of any severity injects nothing.
- **Disjoint reference and stream, fresh per run.** Otherwise reference rows leak into the stream and understate false alarms.
- **Deterministic seeds.** Seeds come from `zlib.crc32`, because Python's built-in `hash()` changes every process.
- **No silent fallback.** Presets raise an error if a dataset file is missing instead of quietly using synthetic data.
- **Quantile bins are de-duplicated on interior edges only,** so zero-inflated features get no zero-width bins while binary features keep their two-way split (a naive de-duplication collapses a binary feature to one bin and its PSI to 0; this is tested).
- **Cached bin edges.** `PSIKLMonitor` computes bin edges once on the reference window; results are tested identical to the uncached version.

## 12. Limitations

- Three datasets, binary labels, numeric features only.
- Detection counts only if an alert fires at any point after onset (up to 20 batches); a stricter detection window would lower sensitivity and raise lag.
- Labels are assumed to arrive in the same batch (a 20% random sample); real feedback is usually delayed.
- Repetitions are different random splits of the same rows, not independent samples of a population, and calibration and evaluation draw from the same pool of rows (through different splits and seeds).
- The conventional floors for PSI, KL and `centroid_dist` were not moved by calibration on any dataset, and they are conservative.
- Pure concept drift is only weakly detectable on some datasets, and the reason PSI/KL do poorly on Adult (a fixed threshold) is a hypothesis that no experiment here isolates.
- The hand-labelled streams were written by the authors and are not real incidents.
- Concept-drift severities (0.25, 0.5, 1.0) were set once and not tuned after seeing results.

## 13. Glossary

| Term | Meaning |
|---|---|
| Batch | a fixed-size chunk of the data stream scored as one unit |
| Reference window | the "normal" data the detectors are fitted on |
| Onset | the stream batch where the shift begins (batch 10) |
| PSI | Population Stability Index: how much a distribution moved across bins |
| KL divergence | how different one distribution is from another |
| KS test | compares two samples by the largest gap between their cumulative distributions |
| Bonferroni correction | multiplying a p-value by the number of tests when many are run at once |
| Brier score | mean squared error of predicted probabilities; lower is better |
| IQR | interquartile range, the 75th minus the 25th percentile |
| Winsorising | clipping extreme values at a chosen percentile |
| Sensitivity | fraction of runs in which a shift was detected after onset |
| False-alarm rate | fraction of clean pre-onset batches that were in an alert state |
| Wilson interval | a confidence interval for a proportion that stays valid near 0 and 1 |
| Score AUC | threshold-free separation between clean and fully shifted batch scores |
| Calibration | choosing thresholds from the noise measured on clean data |
